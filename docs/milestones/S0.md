# S0: Taisce "BFS-plus", hosted

Taisce's first stage ([../filesystem.md](../filesystem.md) §2), developed
on Linux ahead of M3, which mounts it on virtio-blk ([../roadmap.md](../roadmap.md),
"M3"). The core is tier 0: Embedded-clean, built in both builds, because
the native `fs` service is this code. Only the device and FUSE glue are
hosted.

**Exit:**
- A Taisce image made by `mkfs.taisce` mounts through FUSE on the desktop.
  Files written there carry typed attributes. A declared index answers a
  query, and a live query reports the write.
- In `td ci`:
  - the crash harness cuts power at every prefix of a recorded write log,
    then mounts and checks invariants;
  - the shadow-model fuzzer compares the file system with an in-memory
    model after every operation and every simulated crash;
  - the query fuzzer compares indexed results with a full scan.
- Budgets, measured hosted from traces, ahead of M3's QEMU numbers
  ([../performance.md](../performance.md)): a live query update after a
  matching write, and a cached 4 KiB read.

| S0a. Devices and the volume | `Taisce` (tier 0, `lib/taisce`): the `BlockDevice` protocol, with a memory device and a recording device for the crash harness (tier 0) and a file device (hosted). Also the superblock (two copies, newest valid wins), CRC-32C (ours, from RFC 3720), the volume layout, and a block allocator over a free-space bitmap that hands out extents. **Done:**<ul><li>Format and open; the superblock copy for each generation is at `generation % 2`.</li><li>Commits write the bitmap, then a barrier, the superblock, and a barrier.</li><li>Tests:<ul><li>RFC 3720's CRC vectors;</li><li>damaged superblocks are rejected, and a torn newest copy falls back one generation;</li><li>the allocator's extents and its persistence;</li><li>every prefix of a recorded commit mounts.</li></ul></li><li>The tests found that `format` had put generation 2 in the slot generation 3 overwrites.</li><li>The Embedded smoke test replays crash prefixes too.</li></ul> | Done |
| S0b. The B+tree | Keys `(ino, kind, sub_key)` as in §3, 16 KiB nodes, insert, delete, range scans, a node cache; tested against an in-memory model. **Done:**<ul><li>`BTree` is one tree over byte-string keys in byte order. The file system encodes `(ino, kind, sub_key)` big-endian, so the FS tree, the index forest and the journal share it.</li><li>Nodes are decoded whole, and split and merge by encoded size: a node under a quarter full borrows from or merges with a sibling, and the root shrinks from the top. Keys go up to 1 KiB and values to 3 KiB.</li><li>`Store` keeps clean nodes in a direct-mapped cache and changed nodes in a sorted list until written (no hashed collections in tier 0).</li><li>`check` verifies order, bounds, even depth, fill and allocation, for tests now and fsck later.</li><li>Tests:<ul><li>9,000 random operations per run against a model, with 8-, 300- and 3,000-byte values and an 8-node cache.</li><li>Lookups, range scans, a write-and-reopen, and every block returned when the tree is emptied.</li><li>The checker catches broken trees.</li></ul></li><li>Decoding whole nodes is simple, not fast; the cached-read budget (S0i) says whether it needs to change.</li></ul> | Done |
| S0c. Transactions and the log | The transaction API is a sorted batch of messages: insert, delete, and blind deltas (§4, from gefs). Transaction groups with an in-memory delta buffer; a write-ahead log for metadata with checksummed records; replay at mount. The crash harness joins `td ci`. **Done:**<ul><li>`Engine` holds trees by ID, with a catalog tree of roots whose own root is in the superblock.</li><li>`apply` takes a batch of `Message`s (insert, delete, and the blind `Delta`s put-bytes and add-u64), sorts it by tree and key keeping order within a key, and applies it atomically with an undo list.</li><li>`commitGroup` logs the changed node and bitmap blocks as CRC-32C records (`Log.swift`), then a barrier (the commit point), then writes them in place with no barrier. When the log is full, a checkpoint (barrier, superblock, barrier) starts a new epoch. Only the current epoch's records are replayed, so stale ones from an earlier pass are never applied.</li><li>Mount replays every complete group and checkpoints. `Engine.check` adds an exact leak check: the blocks in use are the reserved ones plus every tree's nodes.</li><li>The crash harness (`tests/taisce/CrashTests.swift`, in `td ci`):<ul><li>Every block-by-block prefix of 20 groups of writes, and random subsets within each barrier window.</li><li>Each crashed image must mount, pass every check, hold exactly the state of a group no older than the last committed one, and take new work.</li><li>Mutation-checked: writing in place before the commit point, or not advancing the epoch, each fails it. A first version passed only because most batches failed; it now asserts that its states change.</li></ul></li></ul> | Done |
| S0d. Files and directories | Inodes, directory entries keyed by name hash, extents, nanosecond times, 64-bit sizes, and an orphan list, so space held by files deleted while open is freed after a crash (a BFS flaw). The shadow-model fuzzer joins `td ci`. **Done:**<ul><li>`FileSystem` provides create, symlink, link, unlink, rmdir, POSIX rename (not into itself; replacing as POSIX does), paged listing by name hash, read, write, truncate, attributes, and open/close.</li><li>Each operation builds its changes in an overlay that its own reads see, then applies them as one batch.</li><li>Inodes are 96 bytes, with nanosecond times and a parent pointer.</li><li>File data is copy-on-write per write:<ul><li>new blocks, unless they were allocated in this group;</li><li>a barrier before the log puts the data first (ordered, as ext4's default);</li><li>replaced and freed blocks are held until the group commits.</li></ul>So data changes atomically with its group.</li><li>Orphans: a file unlinked while open is freed at its last close, or at the next mount.</li><li>The engine gained `floor` lookups. `FileSystem.check` (what fsck will run) verifies entries, types, link counts, parents, reachability, and that no block is in two extents. With the engine's count, nothing is leaked.</li><li>The shadow fuzzer (`ShadowFuzzTests.swift`, in `td ci`):<ul><li>Three seeds of 1,500 random operations against a POSIX model, with every error matched and the whole tree and every byte compared after each step.</li><li>About 130 crashes a run. Each mounts the device as it is, unsynced data included, and must equal the model as of the last sync.</li><li>Mutation-checked: writing over committed blocks, not zeroing the tail on truncate, and dropping rename's link counts each fail it.</li></ul></li><li>Writing it found a real bug before any run: extent lookups didn't see an operation's own pending changes, so a truncate that splits the tail extent could double-free blocks.</li></ul> | Done |
| S0e. Unicode | The UCD as data with provenance; our own NFC normalization and full case folding (UAX #15, UCD CaseFolding.txt), passing NormalizationTest.txt. **Done:**<ul><li>`data/unicode` holds four UCD 18.0.0 files and the Unicode License v3, copied from Fedora's `unicode-ucd` package, with hashes in PROVENANCE.md.</li><li>`ucdgen` turns them into sorted tables: combining-class ranges, fully expanded canonical decompositions, primary composites (excluding Full_Composition_Exclusion, derived as UAX #15 §5 defines it), and full case folding. That's 2,081 decompositions, 961 composites and 1,606 foldings.</li><li>`TDUnicode` (tier 0, both builds) has strict UTF-8, NFD, NFC with Hangul by formula, full case folding, and `Text.normalized` and `Text.caselessKey` (D145, canonical caseless matching) for Taisce.</li><li>Tests:<ul><li>All of NormalizationTest.txt, and every code point it doesn't list is unchanged.</li><li>The committed tables match the data.</li><li>Folding cases, and folding is stable for every code point.</li><li>UTF-8's invalid forms are refused.</li></ul></li><li>Mutation-checked: loosening composition's blocking rule fails 1,092 conformance cases.</li></ul> | Done |
| S0f. Attributes, indices, the journal | Typed attributes (§6), inline up to about 2 KiB, then overflow keys. Declared indices with background back-fill and the default set (`name`, `size`, `mtime`, `sys:type`). The persistent change journal, with `seq`. **Done:**<ul><li>Attributes (`AttributeStore.swift`):<ul><li>nine kinds, each its own key;</li><li>names need a namespace, and names and strings are stored in NFC through TDUnicode;</li><li>values over 2 KiB go to 3 KiB overflow chunks, up to 16 MiB.</li></ul></li><li>Indices:<ul><li>each is its own tree, keyed by an order-preserving encoding of the value (integers sign-flipped, IEEE total order for doubles, strings escaped and terminated, in exact or caseless collation) plus the inode;</li><li>a registry tree records each index's kind, collation, state and back-fill cursor;</li><li>the defaults are `name` (keyed with the directory, so each hard link counts), `size`, `mtime` and `sys:type`, kept by every operation in the same batch. Every inode write goes through one function that keeps `size` and `mtime`;</li><li>`declareIndex` maintains a new index at once, and `backfill(budget:)` fills in existing data from its cursor, idempotently;</li><li>`indexLookup` serves equality lookups until S0g's queries.</li></ul></li><li>The change journal: a tree keyed by `seq`, written in the same batch as each change (data writes once per file per group). A failed operation gives its numbers back. It supports resume-after and trimming.</li><li>`check` rebuilds every ready index from the nodes and compares it.</li><li>The fuzzer sets and removes attributes (some overflowing) and declares a caseless index partway through, back-filled a step at a time. It compares every attribute after each step, and index lookups with the model.</li><li>Mutation-checked: a stale index entry after an attribute removal, a stale name entry after a removal, and a back-fill that indexes nothing each fail. The first got through until attribute operations went from 2% to 10% of the fuzzer's steps.</li></ul> | Done |
| S0g. Queries | Query language v2 (BFS infix plus typed literals, ranges, `in`, `~=`, `order by`, `limit`), a planner that needs an index unless asked to scan, and live queries that resume from a `seq`. The query fuzzer joins `td ci`. **Done:**<ul><li>`Query.swift`: the grammar, BFS's syntax plus:<ul><li>typed literals: KiB…TB units on whole numbers and decimals (`4.5MB`), and UTC dates and times;</li><li>`..<` and `...` ranges, `in [...]`, `~=`, `order by … desc`, and `limit`;</li><li>`*` and `?` wildcards, with `\` escapes.</li></ul>Errors give the byte where parsing failed.</li><li>`QueryEngine.swift`:<ul><li>Index ranges only propose candidates; every candidate is re-checked against the whole query with its real values, so an index can make a query slower but never wrong.</li><li>Equality, caseless equality, lists, ordered ranges (only where index order is value order), and wildcards with a literal prefix (backing off one character under folding) are indexable. `!=` and `!` aren't.</li><li>An `&&` takes its smallest indexable part, and an `||` needs every part. A query no index serves fails with `.needsIndex` unless asked to scan. A missing attribute or a mismatched type makes a term false.</li></ul></li><li>Live queries: `live` returns the results and a journal position, and `update` re-checks each node (and parent) the journal names after it, giving added, removed and changed, each with its `seq`. A position past the journal's end (a crash) or trimmed away gives `.journalTrimmed`.</li><li>For live queries, S0f's journal now records every write and the directories each change touches. Nodes record their names (`(ino, NAME, dir + name)`, checked against directory entries) so `name` terms can be evaluated.</li><li>The query fuzzer (`QueryFuzzTests.swift`, in `td ci`):<ul><li>Three seeds of about 500 random queries over 200 files, with indexed, unindexed and wrongly typed attributes.</li><li>The index, a full scan, and an independent reference evaluator (reading through `stat`, `attribute` and `list`) must agree. Three live queries must equal the reference after every round of changes.</li><li>It found that the reference and the library disagreed on wildcards in `in [...]` lists. The library's reading (each element as `==`) is kept, and pinned by a test.</li><li>Mutation-checked: `<=` scans that stop short, an `||` that skips an unindexable part, and live updates that never remove each fail it.</li></ul></li></ul> | Done |
| S0h. The tools | `mkfs.taisce`, `fsck.taisce`, and `taisce-fuse`, which speaks the `/dev/fuse` protocol itself and mounts through the host's `fusermount3` | **Done:**<ul><li>`mkfs.taisce [-L label] [-s size] [-l log] IMAGE` gives the root to its user, as mkfs.ext4's root_owner does.</li><li>`fsck.taisce IMAGE` mounts (replaying the log, freeing orphans) and runs `FileSystem.check`.</li><li>`taisce-fuse IMAGE MOUNTPOINT`:<ul><li>`lib/taisce-host`: the FUSE 7 protocol written from the kernel's UAPI header, with no libfuse; a server mapping operations to `FileSystem` and errors to errno; and the mount. `fusermount3` passes `/dev/fuse` back over `_FUSE_COMMFD`, received by a TDLinux shim since `CMSG_*` are macros; with `auto_unmount` it stays behind and is reaped on a thread.</li><li>Inode numbers are node IDs.</li><li>Typed attributes are `user.` xattrs: `KIND:text` for typed values, plain for strings.</li><li>`/.taisce/{query,live,index}` are control files: `echo QUERY > query; cat query`; `cat live` streams `+`, `-` and `~` lines, its reads held until a change; `index` declares indices.</li><li>It commits on fsync and syncfs, at unmount, after an idle second, and when a group grows large.</li><li>SIGINT and SIGTERM unmount (the handler sets a flag; a thread watches it), and the loop ends when the kernel lets go.</li></ul></li><li>Tests (`tests/taisce-host`):<ul><li>20 structure sizes and 8 field offsets against the host's `<linux/fuse.h>`;</li><li>requests straight into the server: INIT, create, write and read, lookup, errors, typed xattrs, readdir, the query file across two opens, and a live read held until a create releases it.</li></ul></li><li>Tried on the desktop: files, directories, copies, typed xattrs, an index, a query, and a live query streaming adds, removals and changes. A 20 MiB file survives SIGTERM, `fsck.taisce` reports clean, and the remount's checksum matches.</li><li>That run found four bugs, all fixed:<ul><li>CREATE's mode was read from the wrong field;</li><li>`fuse_setxattr_in` is its 8-byte compatible form unless `SETXATTR_EXT` is negotiated;</li><li>an ignored SIGCHLD is inherited and breaks `fusermount3`'s own `waitpid`;</li><li>a signal handler in `main.swift`'s top-level code is main-actor-isolated and traps off the main thread.</li></ul>A new file's owner is now set in the same batch as the file, so a live query sees one change.</li></ul> | Done |

## Decided for this stage (2026-10-09)

1. **FUSE mounts through the host's `fusermount3`.** `taisce-fuse` speaks
   the kernel's FUSE protocol itself, with no libfuse. It spawns the setuid
   `fusermount3`, which opens `/dev/fuse` and passes the descriptor back
   over a socket. That makes the helper a host tool, like the kernel, and
   the mount is visible to the whole desktop. The alternatives were a
   user-namespace mount only its own processes see, and no mount in S0.
2. **Unicode data comes in now.** The UCD files are third-party data with
   recorded provenance, as `vk.xml` is. NFC normalization and full case
   folding are ours, from UAX #15 and the UCD, tested against
   NormalizationTest.txt. The text stack reuses them. Deferring would
   have meant byte-exact strings, ASCII-only folding and an index rebuild
   later.
