# M0: Groundwork

The milestone as the roadmap states it is in [../roadmap.md](../roadmap.md)
("M0: Groundwork"). This file splits it into steps. Each step ends with its
tests passing in both builds (SwiftPM hosted, CMake Embedded), and a step's
row says what was measured.

**Exit:** a protocol defined once has a Swift client, a C client and a
Swift server, and they exchange a message carrying a handle, in a test.
**Met by M0f**, `tests/milestones/M0ExitTests.swift` (2026-10-09). M0
closes when M0g and M0h are done too.

| Step | Content | Status |
|---|---|---|
| M0a. Layout and build | `.swift-version` (6.4.0, as croi); SwiftPM for hosted code and tools; CMake/Ninja building tier 0 libraries as Embedded Swift with croi's flags (strict memory safety, `Lifetimes`, `-Werror EmbeddedRestrictions`) so tier 0 code is proved Embedded-clean on the host; `CLAUDE.md` build commands; a first test in each build. Both builds pass; the Embedded build seeds `-Osize` into the cache, since CMake overwrites the toolchain file's `_INIT` flags | Done |
| M0b. The wire format | `IPCWire`, tier 0: the message header (transaction id, 64-bit hashed ordinal, flags), little-endian 8-byte-aligned encoding over `RawSpan`/`MutableRawSpan`, handles in a side array, epitaphs, cancel by transaction id; golden-byte tests; allocation-free and Embedded-clean. The rules are in [../wire-format.md](../wire-format.md). All safe Swift: no `unsafe` anywhere, using 6.4's bounds-checked, byte-order-aware `RawSpan` loads and `MutableRawSpan` stores. Ordinals use FNV-1a, not FIDL's SHA-256, so no crypto is needed at build time. Golden bytes are checked in both builds, and nine hostile-message cases are rejected | Done |
| M0c. In-process transport | Hosted: channel pairs, a handle table with index plus generation (principle 12), events as the first handle-carrying object, waiting; a C ABI over it for the C client. `lib/ipc/host` (`IPCHost`) stands in for croi's calls with Zircon's semantics: a write consumes its handles even on failure, and a channel can't carry itself or its peer. A short read leaves the message queued and reports the sizes needed. Waits take absolute monotonic deadlines and are cancelled by a close. Handles carry rights. Swift owns handles through a `~Copyable` `Handle` that closes on drop; C uses `td_kernel.h` (hand-written, `td_` prefix as sdk.md §12). 10 tests, three of them from C, passed 200 runs in a row. Found a Swift 6.4 miscompile (a typed-throws closure passed to a `rethrows` method) and recorded it in CLAUDE.md with a reproduction | Done |
| M0d. `@IPCProtocol` | The macro: `Client` and `Server` types for request/reply, `@oneway`, `@event`, `@since(n)`, typed throws; `~Copyable` messages that move handles; decoding as `~Escapable` views into the receive buffer. **Done:**<ul><li>`lib/ipc/macros` generates `<P>Client`, `<P>Handler`, `<P>Server` and `<P>Event` from a protocol's syntax.</li><li>`lib/ipc/runtime` (`IPC`) is the seam generated code calls, and the only part M3 reimplements over croi.</li><li>Fields are integers, `Bool`, `String` (validated UTF-8) and `Handle` (moved with `consuming`); the server checks every padding byte.</li><li>A typed error is an `Int32` enum with positive codes, sent as an error reply (a new header flag, in wire-format.md); unknown methods get `notSupported`.</li><li>Events that arrive during a call are queued.</li><li>Ordinals come from `IPCWire.methodOrdinal`; a collision is a compile error.</li><li>Tests: three end-to-end with the server on another thread (200 runs clean), and nine refusals with their messages.</li></ul>**Left for later, deliberately:**<ul><li>Strings decode as copies, not `~Escapable` views, until a server needs zero-copy.</li><li>Each message allocates a 64 KiB buffer.</li><li>Events can't carry handles.</li><li>A server takes one request at a time, so a cancel always finds its call already answered.</li><li>Generated code is proved Embedded-clean only at M3, when the runtime runs over croi.</li></ul> | Done |
| M0e. `idlc` | Reads the same Swift files with swift-syntax: emits a C header plus encoders and decoders, records an API baseline and fails on an incompatible change, writes protocol documentation. **Done:**<ul><li>The macro's parser and layout model moved into `IPCModel`, so `idlc` and the macro read a protocol identically.</li><li>`lib/ipc/c/include/td_wire.h` is the wire format in C, header-only and written from wire-format.md. It has a UTF-8 validator (Unicode §3.9) and a call helper.</li><li>`tools/idlc` writes:<ul><li>per-protocol C headers: constants, error codes read from the error enum, request encoders, reply and event decoders, call wrappers;</li><li>Markdown pages with each message's layout;</li><li>sorted text baselines. A removed or changed method, a new method without a higher `@since`, or a missing or backwards version bump fails with exit 1.</li></ul></li><li>The headers compile clean under `-Wall -Wextra -Wpedantic -Wconversion -Werror` (C11, C23).</li><li>Tests (6):<ul><li>the checked-in header, page and baseline match a fresh run;</li><li>C encodes the same bytes as Swift;</li><li>C decodes Swift's reply and rejects three hostile variants;</li><li>C's UTF-8 validation agrees with Swift's on 17 cases;</li><li>the evolution rules, one by one.</li></ul></li><li>The C side is client-only for now.</li></ul> | Done |
| M0f. The exit test | One protocol: a Swift client and a C client call a Swift server over the in-process transport, and a message carries a handle both ways. **Done:** `tests/milestones/M0ExitTests.swift`, over the protocol in `tests/ipc/echo/Echo.swift`.<ul><li>The Swift client uses the macro's `EchoClient`; the C client (`tests/ipc/c/idl_c_tests.c`) uses idlc's `echo.h`. Both call the same Swift `EchoServer`.</li><li>Each call covers a reply, the method's own error (C sees `ECHO_ERROR_TOO_LONG`), one-way requests, a later call that sees their effect, and an event handle sent and returned.</li><li>A user signal set before sending shows the same object came back.</li><li>Passed 200 runs in a row.</li></ul> | Done |
| M0g. `td bench` and the budget report | Clean and incremental build time per component as the first budgets ([../performance.md](../performance.md)); history per machine; a `ci` entry point that runs both builds, the tests and the bench. **Done:**<ul><li>`tools/td` measures clean builds (hosted, Embedded), a no-change build, and an incremental rebuild per component (touch one source).</li><li>Each measurement is the median of 5 repeats (3 for clean builds), in its own scratch directory.</li><li>Judgment is against the median of the last 5 runs recorded for this machine (`bench/history/<host>.tsv`): more than 10% and more than 0.25 s slower fails. The rule is unit-tested in `lib/bench`.</li><li>`--record` stores only a passing run; `--accept` records a regression as an open decision.</li><li>`td ci` runs the hosted build and tests, the Embedded workflow, each protocol's baseline check, then the bench. A broken baseline failed it twice over (the outputs test and idlc).</li><li>First numbers (Ryzen 7 9700X): clean hosted 17.9 s (swift-syntax comes prebuilt), clean Embedded 1.3 s, incremental 1.6 to 3.2 s.</li><li>Kept until the tracer exists (M1): a failing run's build logs. performance.md asks for its trace.</li></ul> | Done |
