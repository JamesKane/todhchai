# N0: M3's services, hosted

The native track's first services ([../roadmap.md](../roadmap.md), "M3")
built on Linux ahead of croi reaching them, the way Taisce S0 was:
- the Node protocol and its SDK helper (architecture §6);
- namespaces with bind, union and sealing (§5);
- the launcher with its manifests (§3);
- the block service and the fs service over it (§11).

Natively these are tier 0 processes on croi. Here they run as hosted
processes on a hosted kernel that copies croi's object model, so that at
M3 they move across by changing the kernel underneath, not themselves.

croi's K7a (jobs, processes, threads, VMARs) and K7b (channels,
eventpairs, calls with deadline donation, IPC flow ids) are in; its ABI is
Zircon's values with croi's own syscall numbers
(`../croi/user/include/croi/syscall.h`).

**Exit** (M3's exit, hosted):
- A hosted boot: the launcher reads its manifests and starts the block
  service, the fs service and a client, each in its own hosted process with
  only the namespace its manifest gives it. The client mounts a Taisce
  volume through `/svc/fs`, writes files with attributes, and gets a live
  query update for them.
- `cat`-style reads of a service's Node tree work (`/svc/fs/status`), and a
  manifest naming a missing service stops the launch with its line.
- A service that exits is restarted by its manifest's policy; its clients
  see the channel close and reconnect.
- In `td ci`: every step's tests, both builds, and the IPC baselines.
- Budgets, from traces: a channel call's round trip, a Node walk and read,
  a 4 KiB block read through the ring, and launch to ready. Trace flows
  join a call, its read and its reply, with croi's flow ids
  ([../trace-format.md](../trace-format.md)).

## Decided for this stage (2026-10-10)

1. **Hosted processes are threads in one Linux process.** Each has its own
   handle table, so a process can use only the handles it was given. Memory
   isn't isolated, so a crash isn't contained: restart policy is tested by
   making a service exit. Real isolation comes natively.
2. **Services reach the kernel through one tier 0 module, `Sys`,** with
   croi's object model and Zircon's values: handles and rights, koids,
   channels, eventpairs, events, ports, VMOs, timers, and jobs, processes
   and threads. SwiftPM builds it over the hosted kernel. At M3 the CMake
   build gives the same module over croi's syscalls. Services import `Sys`
   and never know which.
3. **Launcher manifests are line-based text,** in the style of Plan 9
   namespace files: one directive a line, our own parser, errors with line
   numbers, and anything unknown fails loudly.
4. **A typed protocol is reached by walking to it,** as in Fuchsia's
   directories: a tree's *service* node (a new `NodeKind`) answers a walk
   with a channel the service serves its protocol on, not Node
   (`/svc/block/device`). Node itself gains no method; its v1 baseline was
   re-recorded for the new kind, since every client is in the tree.
5. **Protocols compose, as FIDL's do** (after reading fuchsia.io and
   RFC-0023): `protocol Directory: NodeIPC.Node, Attributes` flattens the
   composed methods with their own ordinals, so a Node client works on a
   Directory channel; no "is a" between generated types. Clients flatten
   the calls of composed protocols of their own library and lend their
   connection to clients of another's (the macro sees only its own file);
   `idlc` resolves composition across files (`--with`). A live query's
   changes come on a channel of their own, as fuchsia.io's watchers do.

|---|---|---|
| N0a. `Sys`, hosted | `Sys` (tier 0): handles that move (`~Copyable`) with rights; koids and `object_get_info`; channels with `channel_call` and deadlines; eventpairs and events with signals and peer signals; ports with `wait_async` and packets; VMOs, mappable; timers; jobs, processes and threads. The hosted kernel grows to all of these, with a handle table per process, and the IPC runtime moves onto `Sys` | Done |
| N0b. IPC types and flows | Structs, vectors, byte strings, optionals and enums, declared with protocols in an `@IPCLibrary` enum (decided 2026-10-10: the macro sees the whole library, so layouts stay static and the macro and `idlc` share one model); `idlc`'s C output, the wire format document and the baselines. Calls go through `channel_call`; generated code computes croi's flow ids and writes FLOW records | Done |
| N0c. The Node protocol | `Node` (walk, stat, readdir, read, write, watch, create, remove) with qids, and the SDK helper that publishes an in-memory tree in about 150 lines. Text leaves (`status`, `ctl`). A service serves its channels from one thread with `IPCDispatcher` (a port; other threads `wake` it to send events) | Done |
| N0d. Namespaces | A process's namespace: paths to channels, bind before/after/replacing with a create member, unions resolved in the client (capped, merged listings without duplicates), sealing that children inherit, `/svc`, `/data`, `/vol`, `/srv`. `mount` attaches a channel and `bind` rearranges held ones (only `bind` in a sealed namespace); paths are cleaned lexically; `/srv` is a board service (`SrvIPC.Board`) whose posted names forward walks to the posting program's tree | Done |
| N0e. The launcher | Manifests; a job and a process per service; namespaces built from what a manifest names, and nothing else; startup handles; restart policies; a manifest naming a missing service or a bad path stops the launch with its line. A hosted boot runs it. A process's `/svc` is a tree the launcher serves for it, forwarding each name to the service's current instance, so clients reconnect after a restart by opening the path again; restarts run on a supervisor thread, and five in 30 s give up | Done |
| N0f. The block service | Submission and completion rings in a shared VMO, signalled through eventpairs; per-request cache policy; a hosted device backend over an image file. Its Node tree (`status`). The ring (`BlockRing`) is tier 0, in both builds; each side kicks the other only when its flag says it is asleep. A session is a channel to `device`: a ring, attached buffer VMOs, and the end of both when the channel closes; a client that breaks the ring's rules is cut off. The dispatcher drains rings on its thread (`IPCDispatcher.watch`) | Done |
| N0g. The fs service | Taisce behind an fs protocol that extends Node (directories, files, attributes, queries, live queries), over a block client. File reads and writes through the channel until croi has streams. `FsIPC.Directory` and `File` compose Node and `Attributes` (decision 5); `/svc/fs/volume` is the volume's root, a directory the service serves itself (`NodeTree.delegate`); watches and live queries hear changes from the change journal at in-memory commit; a group commits a second after a change, or on `Directory.sync` | Done |
| N0h. The exit | The hosted boot of the exit, and the budgets in `td bench`. The boot's manifests (`boot/manifests`) run block, fs and `catalog`, a client that mounts `/svc/fs/volume` at `/data`, catalogues songs with typed attributes, sees a live query's update, and remounts when fs restarts; `tests/milestones/N0ExitTests.swift` runs them, kills fs (`Launcher.kill`) and checks the reconnect. `n0-bench` measures the budgets from zones and IPC flows (`td bench --programs`; `td trace summary` lists flows) | Done |
