# A0: the AML interpreter, hosted

Our ACPI interpreter (F track; [../architecture.md](../architecture.md)
"ACPI" and §20), developed on Linux ahead of M3, whose devmgr enumerates
ACPI with it ([../roadmap.md](../roadmap.md), "M3"). It is written from
the ACPI 6.5 specification, with no ACPICA (principle 29). The library,
`TDACPI` in `lib/acpi`, is tier 0: Embedded-clean, built in both builds,
because devmgr runs this code. It does no I/O itself: operation regions,
sleeping, notifications and the OS's answers to `_OSI` go through a host
interface, which devmgr implements natively and tests implement with
fakes that record every access.

**Exit:**
- Every table in the corpus loads with no unknown opcode and no trap:
  this machine's DSDT and SSDTs, and QEMU's for x86 (q35 and pc), arm64
  (`virt`) and riscv64 (`virt`).
- On this machine, our enumeration of its tables matches Linux's view of
  the same namespace (`/sys/bus/acpi/devices`, which needs no root): the
  same devices at the same paths, with the same `_HID`, `_UID`, `_ADR`
  and `_STA`.
- `_CRS` resource templates and `_PRT` routing decode for every device
  that has them in the corpus.
- No input traps the interpreter. A fuzzer mutating the corpus's tables
  runs in `td ci`, with limits on loop time, recursion and memory.
- Budgets, from traces: loading the corpus's largest DSDT, and evaluating
  `_STA` across every device.

## Decided for this stage (2026-10-09)

1. **Real tables stay out of the tree.** Firmware tables are vendor (or,
   for QEMU's, GPL-licensed) binaries. The corpus lives in a gitignored
   directory that `td acpi` fills: this machine's tables, copied once with
   root, with a snapshot of Linux's `/sys/bus/acpi/devices` view as the
   oracle; QEMU's regression fixtures, fetched at a pinned commit. Tests
   over the corpus skip when it's absent. `td ci` always runs the
   synthetic tests, whose AML is built by an encoder of our own in the
   test suite.
2. **The library is `TDACPI`**, like `TDCrypto` and `TDUnicode`: tables,
   the AML interpreter and resource decoding together.
