# M1: Hosted SDK core

The milestone as the roadmap states it is in [../roadmap.md](../roadmap.md)
("M1: Hosted SDK core (H)"). The API it builds is [../sdk.md](../sdk.md)
§1 to §8 and §12. Everything runs on Linux, as an ordinary Wayland client
(architecture §18): it speaks the Wayland wire protocol itself, and it uses
the host's Vulkan loader and driver.

**Exit:**
- **minimal:** at most 13 calls, and 0 idle wakeups.
- **synth:** 0 underruns at 128 frames, with a compiler-checked callback.
- **game loop:** p99 frame error at most 1 ms against present feedback.

Each is read from traces ([../performance.md](../performance.md)), so the
tracer comes first.

**Development machine:** brimstone (Ryzen 7 9700X, RTX 5070 Ti, Radeon iGPU
through RADV, KDE Plasma on Wayland, PipeWire). The reference machine's
numbers come with M8.

## Decided for this milestone (2026-10-09)

1. **Audio on the Linux host: PipeWire's native protocol, ours.** The
   hosted SDK speaks PipeWire's socket protocol directly, as it does
   Wayland's (architecture §18): SPA pod encoding and the core, registry
   and client-node objects, written from PipeWire's protocol
   documentation. It's the largest of the options, but it follows the rule
   and coexists with the desktop. The alternatives were ALSA's kernel PCM
   interface (it needs exclusive use of a device PipeWire holds) and
   loading the host's `libpipewire` (it bends the rule).
3. **Presenting Vulkan frames: dmabuf through our own Wayland.**
   `VK_KHR_wayland_surface` takes libwayland's `wl_display`, and we speak
   Wayland ourselves, so the host's Vulkan WSI isn't used. Loinnir renders
   into exportable images and presents them with `zwp_linux_dmabuf_v1`,
   as Todhchai's compositor will take GPU buffers. The alternatives were a
   copy into shared memory (too slow for the frame-error target) and
   loading libwayland for WSI only (it bends architecture §18).
2. **The offline shader compiler: glslang, with GLSL.** It's packaged in
   Fedora (`sudo dnf install glslang`) and is a toolchain under principle
   29. Slang can follow later.
4. **The hosted libtodhchai is full Swift.** The C ABI is exported with
   `@c` from a SwiftPM dynamic library over the hosted SDK, which links
   the Swift runtime. The header and the ABI are the real ones. The
   Embedded build that sdk.md §12 calls for comes when the SDK runs on
   croi, where its platform code is tier 0. Zig (Fedora's 0.16) and Odin
   (the build at /opt/odin, as VectraOS-Odin uses) are toolchains:
   `td ci` compiles with them where they're installed.
